## 2024-06-15 - [SSRF vulnerability via custom AI provider baseUrl]
**Vulnerability:** The application accepted custom `baseUrl` inputs for connecting to custom AI providers (like Ollama and OpenAI-compatible endpoints) without validating the URL. This could allow Server-Side Request Forgery (SSRF) where an attacker could query internal AWS metadata endpoints (e.g. `http://169.254.169.254/`).
**Learning:** The gateway functionality requires allowing user-defined hostnames for local AI endpoints (like `localhost` or `127.0.0.1`), making simple protocol-level filtering insufficient. A full SSRF protection implementation using DNS lookups was necessary.
**Prevention:** Implement strict URL validation on all outgoing `fetch` requests using user-provided URLs. Use Node.js `dns.lookup` to perform an asynchronous DNS resolution and verify that the target IP address does not match internal infrastructure (like `169.254.169.254`), while explicitly allowing known loopback addresses for local development tools.
