## 2024-05-18 - Prevent DNS Rebinding SSRF on AI Gateway Custom Provider URLs
**Vulnerability:** The AI gateway allowed custom endpoints (e.g. `baseUrl`) to be provided for local models and generic providers without validating the target IP. This exposed the gateway to Server-Side Request Forgery (SSRF) vulnerabilities, specifically allowing an attacker to ping internal metadata endpoints such as AWS instance metadata (`169.254.169.254`) by exploiting DNS resolution or providing internal IP addresses.
**Learning:** Checking the hostname/URL string is insufficient because of DNS rebinding attacks. The host might resolve to a safe IP at the time of the check but a malicious internal IP at the time of the request. Furthermore, local providers like Ollama often need to connect to loopback addresses (`127.0.0.1` or `[::1]`), so standard SSRF preventions that block all private IP ranges break functionality.
**Prevention:** Always perform an asynchronous DNS resolution on the parsed hostname using `node:dns` `lookup` and validate the *resolved IP address*. Explicitly block internal metadata IP addresses like `169.254.169.254` while permitting necessary loopback addresses for local integration. Fail securely (deny-by-default) if the URL is invalid.
