## 2025-02-28 - SSRF Vulnerability in AI Gateway Provider URLs
**Vulnerability:** The AI Gateway (orchestrator and models fetcher) accepted arbitrary `baseUrl` inputs from the client without any validation or sanitization, passing them directly to the native Node.js `fetch` client.
**Learning:** This allowed for Server-Side Request Forgery (SSRF), where an attacker could provide a malicious `baseUrl` (like `http://169.254.169.254/latest/meta-data/`) to trick the backend server into retrieving internal cloud metadata credentials. Additionally, failing to disable `fetch` redirects meant an attacker could bypass initial URL validation by providing an external server URL that simply responded with an HTTP 302 redirecting to an internal IP.
**Prevention:** Always validate and sanitize user-provided URLs before fetching them on the backend. Block private/internal subnets (specifically metadata IP `169.254.169.254`) and enforce strict schema allowlists (`http:` and `https:`). Crucially, set `redirect: 'error'` in `fetch` calls to prevent HTTP redirect-based SSRF bypasses.
