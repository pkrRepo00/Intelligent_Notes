## 2024-05-18 - SSRF in AI Gateway
**Vulnerability:** The AI Gateway (orchestrator.ts) allows users to specify custom provider URLs (e.g., `baseUrl`) without validation. This allows attackers to make the server send requests to internal resources, like the AWS metadata endpoint (169.254.169.254), leading to Server-Side Request Forgery (SSRF).
**Learning:** Even if the fetch API is used internally, we must validate URLs to ensure they don't resolve to internal or restricted IP addresses, especially since `node-fetch` and standard `fetch` follow redirects by default and don't block internal IPs. Also, TOCTOU (Time-of-Check to Time-of-Use) DNS rebinding attacks can bypass simple URL string validation.
**Prevention:** Implement a custom `undici` Agent with a `lookup` function to validate the resolved IP address during the connection phase. Block access to known internal metadata endpoints like 169.254.169.254. Ensure `redirect: 'error'` or `redirect: 'manual'` is set to prevent attackers from bypassing initial validation via HTTP redirects.
