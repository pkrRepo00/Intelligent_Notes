## 2024-06-25 - SSRF Vulnerability in Orchestrator and ModelsFetcher
**Vulnerability:** The AI gateway passes user-provided `baseUrl` directly to `fetch` calls without validation, leading to potential SSRF (Server-Side Request Forgery). The memory indicates that we should validate custom provider URLs (like `baseUrl`) to ensure they use valid HTTP/HTTPS protocols and do not point to internal metadata endpoints. Additionally, memory states `fetch` follows HTTP redirects by default, which can bypass initial input validation via HTTP 302 redirects to internal IPs, requiring `redirect: 'error'` or `redirect: 'manual'` in fetch configurations.
**Learning:** `baseUrl` input from users was not validated, allowing them to provide URLs pointing to local internal addresses like `169.254.169.254`. Furthermore, TOCTOU DNS rebinding issues exist and must be prevented by either private IP blocklist or handling IPs safely. However, Memory also specifies "permit loopback addresses (like 127.0.0.1, localhost, or [::1]) across all ports to avoid breaking local AI provider integrations".
**Prevention:** Implement an SSRF validation function using `node:dns` lookup and prevent access to sensitive IPs (metadata IPs), while specifically allowing local testing IPs (`127.0.0.1`, `localhost`).
