## 2025-02-28 - SSRF Vulnerability in AI Gateway
**Vulnerability:** The AI Gateway (`server/orchestrator.ts`, `server/modelsFetcher.ts`, `server/server.ts`) passes user-supplied URLs (like `baseUrl`) directly to native Node.js `fetch` without validating the host/IP. This allows SSRF (Server-Side Request Forgery) attacks where a user can make the server ping internal metadata endpoints (e.g. `169.254.169.254`).
**Learning:** Node.js native `fetch` doesn't provide a way to hook into the DNS resolution process to prevent TOCTOU (Time-of-Check to Time-of-Use) DNS rebinding attacks while maintaining HTTPS/SNI support easily. To properly secure it, we must use `undici` with a custom `Agent` and a custom `lookup` function to validate the IP address *after* resolution and *before* connection.
**Prevention:** Always use `undici` with a DNS-level verification `Agent` when making server-side requests to user-controlled URLs. Allow loopback (localhost/127.0.0.1) for local integrations (like Ollama), but block `linkLocal` (metadata endpoints), `private`, etc.
