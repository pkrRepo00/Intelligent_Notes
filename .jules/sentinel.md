## 2024-05-18 - [Critical] SSRF Vulnerability via Custom LLM Providers
**Vulnerability:** The application fetches external AI APIs (like Ollama or OpenAI compatible endpoints) using user-supplied URLs without validation.
**Learning:** This could allow attackers to scan internal networks or access sensitive metadata endpoints (like AWS 169.254.169.254) by passing them as custom provider base URLs. Fetching directly with user-provided URLs is dangerous because it allows SSRF. Validating the URL via DNS lookup and then passing the original string to `fetch` is vulnerable to TOCTOU DNS rebinding attacks. Native Node `fetch` does not support custom dispatchers securely without breaking TLS/SNI.
**Prevention:** In this specific scenario where native fetch is used, the TOCTOU risk is mitigated by checking if the resolved IP points to metadata endpoints and using `redirect: "error"` in the fetch call to prevent 302 bypasses. However, a perfect fix would require using a custom HTTP agent (like Undici) overriding the `lookup` function to validate the IP during the actual connection.
